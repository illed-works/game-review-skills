# ゲームメカニクス特許の地雷原マップ

## 大前提

特許リスクはこのスキルで扱う領域の中で**最もAIの限界が大きい**。特許は「クレーム(請求項)」の文言で権利範囲が決まり、その解釈は弁理士の専門領域。またゲーム特許の多くは公開されていても知られておらず、網羅的なクリアランス調査はAIには不可能。

したがってここでの仕事は3つに限定する:

1. 企画のメカニクスが**紛争実績のある地雷原領域**に入っていないかの照合
2. 入っている場合、関連する特許・紛争の**最新状況をweb検索で確認**
3. 「弁理士に投げる質問文」を具体的に作る(さらに深掘りする場合は expert-prep.md の相談パック作成へ)

「特許的に問題なし」とは絶対に書かない。書けるのは「既知の紛争領域との重複は見つからなかった(網羅調査ではない)」まで。

## 紛争実績のある地雷原領域

企画のメカニクスがここに触れたら要調査フラグ。各領域とも、**具体的な特許番号や勝敗の断定は記憶で書かず、検索して現状を確認する**(特許は失効・無効審判・和解で状況が変わる):

- **タッチ操作系**: スマホの独自タッチ操作(スワイプ操作の吸着・補正等)。日本で大型訴訟の実績がある領域
- **ガチャ・抽選演出**: 抽選結果の演出、確定演出、天井システムまわり。パチンコ・パチスロ由来の演出特許も近接
- **キャラクターの捕獲・育成・騎乗**: フィールド上でのキャラ捕獲、乗り物としてのキャラ切替等。近年の大型訴訟で注目された領域
- **位置情報ゲーム**: 現実位置とゲーム内オブジェクトの対応付け、すれ違い通信系
- **音楽ゲームの入力判定**: 譜面と入力タイミングの判定・表示方式。歴史的に権利行使が活発だった領域
- **ローディング画面の演出**: ロード中のミニゲーム(著名な特許は失効済みとされるが、周辺特許の有無は個別確認)
- **オンラインマッチング・通信対戦の仕組み**: マッチメイキング、非同期対戦、ゴーストデータ
- **UIの省力化系**: オートプレイ、スキップ、まとめて実行等の便利機能の実装方式
- **フォロー・応援などソーシャル連動の報酬設計**

## チェックの型

1. 企画書からコアメカニクスを5〜10個に分解する(「◯◯を△△すると□□になる」の粒度)
2. 上記の地雷原領域と照合する
3. 触れた領域について「(メカニクス名) 特許 訴訟」「(著名タイトル名) 特許」等でweb検索し、現在進行中・確定済みの紛争と特許の状況を確認する
3.5. **重大度をつける前に、その特許・紛争が今も生きているかを確認する**。失効・放棄済みの特許、和解や無効審決で決着済みの紛争を、現役のリスクとして報告しない。確認できない場合は「係属状況を確認できず」と明記して重大度を保留する
4. リスクの書き方: 「本企画の◯◯(仕様書△章)は、□□社が権利行使した実績のある領域と重なる。ただし本企画の実装は◇◇の点で異なるため、抵触の有無はクレーム解釈が必要 → 要専門家相談リストへ」

## リスクを下げる設計上の工夫(回避策の引き出し)

- 紛争実績のある「特定の実装方式」を避け、同じ体験を別方式で実現できないか検討する(特許は方式を保護するもので、体験そのものは保護しない場合が多い)
- 業界で広く一般化している実装(公知技術)に寄せる
- 危険領域のメカニクスが企画のコアでないなら、外すか後回しにする選択肢を提示する
- コアである場合は「実装前に弁理士のクリアランス調査(対象を絞れば数十万円規模から)」を予算項目として企画書に載せることを提案する(これはgame-biz-reviewのコスト章とも接続する)

## 自社の防衛

指摘だけでなく、逆に**本企画の独自メカニクスが出願候補にならないか**も1〜2個挙げる。小規模な開発体制でも防衛出願の価値がある独自性が見つかることがあり、投資判断の材料になる。ただし出願には費用と時間がかかるため、規模に見合わない場合は「候補としてはあるが、今の体制では優先度が低い」と正直に添える。
