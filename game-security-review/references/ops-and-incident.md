# ops-and-incident.md — 破られた後どうするか

**穴をゼロにはできない。** だから「破られたときに、気づけるか・止められるか・元に戻せるか」が同じくらい重要になる。ここが用意されていないタイトルは、小さな穴でも致命傷になる。

## A. すでに事故が起きている/疑いがある場合(最優先)

レポートを書く前に、この順で判断を出す。

### 1. 今すぐ止めるべきか

以下のどれかに当てはまるなら、**メンテナンスまたは該当機能の停止を最初に提案する**:

- 課金アイテム・通貨が現在進行形で増やせる状態
- 個人情報が取得可能な状態
- 管理系の権限が奪われている可能性がある

**判断の軸は「止めた損失」と「動かし続けた損失」の比較**。ブラウザゲームは修正の反映が速いので、止めて直す選択肢を過小評価しない。一方で「特定のAPIだけ止める」「該当機能だけ無効化する」で足りることも多いので、**全停止しか手がないのかは確認する。**

### 2. 被害範囲を調べる

- いつから穴が存在したか(デプロイ履歴と突き合わせる)
- 何件・誰が使ったか(APIのアクセスログ、通貨増減のログ、購入履歴)
- **ログが残っていない場合、範囲は確定できない。** その事実自体をレポートに書く(推測で「被害は軽微」と書かない)

### 3. 鍵が漏れていたら、まず無効化

`client-exposure.md`のとおり、削除ではなく**無効化と再発行**。順序は「無効化 → 新しい鍵をサーバー側に配置 → クライアントから鍵を排除する改修」。

### 4. 直した後にやること

- 不正に得られたアイテム・通貨の**回収方針**を決める(全回収 / 一部回収 / 放置)。回収はプレイヤーとの摩擦を生むので、基準を先に決めて一貫して適用する
- 正当なユーザーへの**補填**が必要か
- **告知するか**。個人情報が関わるなら告知と当局への報告が必要になりうるので、この時点でgame-legal-reviewと法務に回す

## B. リリース前に用意しておくべきもの

以下がないままリリースするのは、それ自体がリスク。**レビューで「機能に穴がない」ことより、ここが空欄であることの方が深刻な場合がある。**

### 1. 記録(ログ)

- 通貨・アイテムの増減が、**いつ・誰が・何によって**変わったか記録されているか
- 課金の処理履歴が残るか
- APIのアクセスログがどれくらいの期間残るか

**記録がないと、事故が起きたとき「何が起きたかわからない」状態になり、回収も補填も告知内容も決められない。** 通貨と課金のログは最低限必須(なければ🟡、課金があるなら🔴に近い)。

### 2. 異常に気づく仕組み

- 通貨・アイテムの発行量が急増したときに気づけるか(日次でよい)
- ランキングに異常値が出たときに気づけるか
- エラー率・アクセス数の急変を検知しているか

完璧な自動検知は不要。**「毎日1回、通貨の発行量と上位ランキングを人が見る」だけでも大半の異常は捕まる。** 非エンジニアでも運用できる形を提案する。

### 3. 止める手段(キルスイッチ)

- ゲーム全体をメンテナンスに入れられるか
- **特定の機能だけ止められるか**(ガチャだけ、ギフトだけ、ランキングだけ)
- 反映にどれくらい時間がかかるか

「サーバー側の設定変更だけで機能を止められる」状態が理想。**クライアントの再ビルドと審査が必要な作りだと、止めるのに数日かかる**(モバイル・Steamで特に重要)。

### 4. 戻す手段

- 直前のバージョンに戻せるか
- データベースのバックアップがあるか、**復元を試したことがあるか**(取っているが戻せない、は実際に起きる)

### 5. 対応する人と手順

- 事故発生時、誰が判断し、誰が作業するか
- 休日・深夜に連絡がつくか
- **外注が実装している場合、緊急対応が契約に含まれているか**(これは非常に見落とされる。契約時に決めておく)

### 6. 報告窓口

- プレイヤーが不具合・不正を報告できる窓口があるか
- セキュリティ上の問題の報告先が用意されているか(善意の報告者が連絡先を見つけられないと、SNSで公開されてから知ることになる)

## C. 不正対策の考え方(過剰にならないために)

- **完全な防止は目標にしない。** コストが無限にかかる上、正当なユーザーの体験を損なう。目標は「割に合わなくすること」と「早く気づいて元に戻せること」
- **正規ユーザーを疑いすぎない。** 誤検知でBANすると、失うのは売上と評判。自動BANより、まず**検知して人が確認する**運用から始める
- **BAN・回収の基準を先に文章にしておく。** 事後に決めると、判断がぶれてプレイヤーの不信を招く。利用規約に不正行為の定義と措置を書いておくこと(文言はgame-legal-reviewに回す)
- **チートが成立した事実を隠さない。** 隠して発覚した場合の信頼の損失の方が大きい。何が起き、何を直し、何を補填するかを説明する
