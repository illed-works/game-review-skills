# レビュー観点チェックリスト

全観点を照合する。企画タイプにより重み付けを変える(IP: 権利観点が最重要 / 運営型: 継続性が最重要 / 買い切り: 回収とスコープが最重要)。

## A. 権利・パートナー(IP・原作・コラボものは最優先で見る。オリジナルIPで外部パートナーがいない場合はこの章をスキップしてよい)

- [ ] 監修フローの有無。特に「会話・関係性・キャラ表現」が商品の中核の場合、監修量が運営負荷の最大要因になることを指摘しているか
- [ ] 契約前に権利元へ確認すべき事項(使用キャラ範囲、関係性・恋愛表現の可否、オリジナル衣装、ボイス収録、**広告可否**、ガチャ条件、SNSシェア可否)のリスト化
- [ ] ロイヤリティ(相場5〜15%)とミニマムギャランティがP&Lに織り込まれているか
- [ ] 監修を軽くする仕組み(テンプレ化、バッチ提出、事前合意)が基盤・営業資産として設計されているか
- [ ] キャラ解釈・カップリング的表現など炎上リスク領域の事前合意プロセス
- [ ] 原作メディア展開(新刊・アニメ・映画)との連動体制

## B. 数値目標とP&L

- [ ] 「そこそこの売上」等の曖昧な目標が数値定義されているか(DAU、D1/D7/D30継続率、課金率、ARPDAU、月商)
- [ ] 月商の3シナリオ(悲観/基準/楽観)と計算式
- [ ] 月次コストの骨格(人件費、コンテンツ制作、インフラ、ロイヤリティ、宣伝)と損益分岐ライン
- [ ] 初期開発費と回収期間。開発体制(従来型/AI駆動/ハイブリッド)による費用差
- [ ] 複数タイトル展開なら「N本中、何本失敗しても黒字が残る構造か」のポートフォリオ視点
- [ ] プラットフォーム手数料(ストア30%等)の織り込み

## C. 横展開・スケールのコスト構造(基盤・シリーズ企画は最優先で見る。単発タイトルで横展開の予定がなければこの章はスキップしてよい)

- [ ] 2作目以降の費用・期間の目標値(1作目比%)。基盤企画の価値は「2作目がいくらで何ヶ月か」で決まる
- [ ] 「流用でゼロになる部分」と「毎回発生する部分」の分解。後者の標準アセットリスト化
- [ ] コストの過半がコードかアセットか。AI駆動開発の圧縮が効く範囲の見極め(アセット・監修は圧縮されない)
- [ ] クリティカルパスの特定(多くの場合コーディングではなくアセット制作と監修)
- [ ] 権利元交渉に使える標準提示パッケージ(費用・納期・仕様の定型)

## D. 運営継続性・コンテンツ供給

- [ ] 商品の中核コンテンツ(会話、シナリオ、キャラ)の消費速度と制作コストの釣り合い。「軽運営」宣言と制作量の自己矛盾
- [ ] コンテンツの階層ポリシー(どこを手書きし、どこを仕組み・テンプレで済ませるか)。組み合わせ爆発(ペア数等)への対処
- [ ] 弾切れ試算(新キャラ・新ステージが何ヶ月で尽きるか)と、尽きた後の売り物ロードマップ
- [ ] 月次運営の標準制作量とその人的コスト上限
- [ ] 周年・大型施策の標準パッケージ。後から追加できる「棚」(上限解放、フルボイス化等)の事前仕込み
- [ ] 撤退設計(撤退ライン、低コスト運営への移行、終了手順、権利元との終了条件合意)

## E. 検証設計

- [ ] プロトタイプ/MVPの確認項目が定性だけになっていないか。GO/NO-GO の定量基準(継続率、起動回数、月商判定)
- [ ] そのプロトタイプで**構造的に検証できないもの**の分離(例: プレースホルダーキャラでは「推し」仮説は測れない)。検証対象の明確化
- [ ] ソフトローンチの判定基準と、未達時に「改修に戻す」条件
- [ ] 実弾でしか踏めないリスク(課金フロー等)の検証方法

## F. 市場実証・競合

- [ ] コア要素それぞれの先行実証例(「何が実証済みか」の整理)
- [ ] 同ジャンルの失敗事例と死因パターン(判断の不在、客層とゲーム構造のミスマッチ、ガワ替え露見、コンテンツ枯渇)、および本企画の対応の対応付け
- [ ] 競合の分類(直接競合/同じ客の時間と財布を奪う準競合/非IPの機構競合)とポジションの空白の特定
- [ ] ベンチマークタイトルが作った「快適さ・品質の期待値」を初期仕様の水準として認識しているか

## G. ゲームデザインと事業の整合

- [ ] コアループに「判断」があるか(回収するだけのアプリ化していないか)。判断軸の明文化
- [ ] ターゲット層とゲーム構造のミスマッチ(キャラを愛でたい層に高難度攻略を要求する等)
- [ ] マネタイズとデザインの矛盾(見た目課金と性能の未分離、完凸前提バランス、パス必須化、広告前提進行)。上限設計・分離設計の有無
- [ ] 課金軸(金)とプレイ軸(時間)の役割分担。感情報酬を課金の壁の向こうに置いていないか
- [ ] 「避けるべきこと」リストの有無(スコープ膨張の防波堤)

## H. 見落とされがちな定番

- [ ] SNSシェア・UGC導線(フォトモード等)。ファン向け企画で欠けていたら指摘(低コスト高効果)
- [ ] 通知・復帰(カムバック)設計。「1日N回起動」を支える装置
- [ ] 図鑑・コレクション完成のUIと報酬
- [ ] サーバー権威型・チート対策の技術方針明記
- [ ] 放置上限・スタミナ等の数値が現行市場の標準とズレていないか
- [ ] 名前のない主要システム(頻出するのに定義章がない概念。例: 親密度が頻出するのに章がない)

## I. ドキュメントとしての品質

- [ ] 数値の仮置きに「確定次第更新」の注記があるか
- [ ] 内部用と外部提出用(権利元・出資者等)で分けるべき内容(競合失敗の実名分析等)の注記
- [ ] 意思決定の記録(何を検討しどう決めたか)が残る構成か
- [ ] 結論・一言要約が事業の勝ち筋(コスト・継続性)まで含んでいるか
